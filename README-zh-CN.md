# tuiUNO

[![CI](https://github.com/dxx114514-stack/tuiUNO/actions/workflows/ci.yml/badge.svg)](https://github.com/dxx114514-stack/tuiUNO/actions/workflows/ci.yml)

一款用 C++17 编写的命令行 UNO 游戏，不依赖任何第三方库。

- **离线人机对战（PVE）** — 1 名或 2 名玩家对战电脑，三档 AI 难度。
- **在线联机对战（PVP）** — 在任意一台机器上开房，其他玩家通过 TCP 加入。
- **中英双语** — 可在菜单中切换，也可用 `--lang` 指定。
- **完整规则** — 标准 108 张牌，另有多项可选的家用规则。

> 英文版见 [README.md](README.md)。

---

## 编译

需要 CMake ≥ 3.16 和支持 C++17 的编译器。已在 MinGW-w64（GCC 14）和 MSVC 上验证；
同一份 CMakeLists 在 Linux 上用 g++ 或 clang++ 也能编译。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

编译产物为 `build/uno`（游戏本体）和 `build/uno_tests`（测试程序）。

```sh
ctest --test-dir build --output-on-failure   # 运行测试
./build/uno_tests                            # 同上，但输出更详细
```

CI 会在每次 push 和 pull request 时，于 Linux（GCC、Clang）、macOS（Clang）和
Windows（MSVC）上编译并运行测试。

## 运行

```sh
./build/uno                       # 进入交互式菜单
./build/uno --lang zh             # 以中文启动
./build/uno --players 2 --diff 2  # 2 个席位，困难难度
./build/uno --help                # 查看全部选项
```

### 人机对战（PVE）

在菜单中选择**人机对战 (PVE)**，然后选择由几名玩家操控（1 名或 2 名；两名玩家共用
同一个终端，界面会在你们之间自动切换），最后选择 CPU 难度。

### 联机对战（PVP）

房主运行权威游戏端；每个客户端只收到属于自己的视图，并提交自己的操作。只需要保证
房主的端口可达即可。

房主：

```sh
./build/uno --host --port 45231
```

房间界面会显示 4 位房间号和一条可直接粘贴的加入命令：

```
  room code : K49K
  address   : 192.168.5.20:45231
  join with: uno --join 192.168.5.20 -p 45231 -c K49K
```

客户端：

```sh
./build/uno --join --host-addr 192.168.5.20 --port 45231 --code K49K
```

空余的席位由电脑补齐，所以两个人也能开四人局。在房间界面或对局中按 `/` 可以聊天。

如果需要跨公网，请做端口转发（Windows 用 `netsh interface portproxy`，其他系统用
`iptables -A PREROUTING -p tcp --dport 45231 -j DNAT ...`），或者让两台机器处于同一局域网。

## 操作按键

| 按键 | 作用 |
| --- | --- |
| `↑` / `↓`、`W` / `S` | 在菜单中移动，移动光标选牌 |
| `1`–`0` | 打出对应位置的牌（超过 9 张后循环） |
| `Enter` | 打出高亮的牌 / 确认 |
| `D` | 摸一张牌 |
| `P` | 过牌（仅在刚摸完牌后可用） |
| `U` | 喊 UNO |
| `C` | 抓漏报：抓住只剩一张牌却没喊 UNO 的对手 |
| `R` `Y` `G` `B` 或 `1`–`4` | 打出万能牌后选择颜色 |
| `Y` / `N` | 质疑万能加四 / 接受罚摸 |
| `/` | 聊天（房间界面与对局中） |
| `Esc`、`Ctrl+C` | 退出 |

## 规则

标准 108 张牌：四种颜色，`0`–`9`（每种颜色 1 张 `0`、`1`–`9` 各 2 张），
禁手 / 反转 / 加二（每种颜色各 2 张），万能牌 4 张、万能加四 4 张。

以下全部可在**规则设置**中开关：

| 规则 | 默认 | 说明 |
| --- | --- | --- |
| 玩家人数 | 4 | 可选 2–4 |
| 每人起手牌数 | 7 | 可选 3–10 |
| 目标分数 | 500 | 率先达到该分数者赢得整局 |
| 加二可叠加 | 关 | 允许用 `+2` 回应 `+2`，把罚摸传下去 |
| 可质疑万能加四 | 开 | 见下文 |
| 万能加四可叠加 | 关 | 允许用 `+4` 叠在待处理的 `+4` 上 |
| 有牌必出 | 关 | 存在合法出牌时禁止摸牌 |
| 弃牌堆回洗 | 开 | 牌堆摸空后回收弃牌堆 |
| 漏报 UNO 罚 2 张 | 开 | 被抓到漏报者摸两张 |
| 开局 7-7 换手 | 关 | 开局按 7-7 规则交换手牌 |
| 组队模式 | 关 | 四人局，席位 0+2 对阵 1+3 |

**万能加四。** 在生效颜色下，手里仍有该颜色牌却打出 `+4`，属于作弊——就像实体卡牌
一样，只有被人质疑才会受罚。下家可以选择质疑：如果出牌者确实持有该颜色，`+4` 被
取消，出牌者收回那四张牌，质疑者摸两张；否则质疑者吃掉全部罚摸（有叠加时可以多于
四张）。

**回合与计分。** 任何一位玩家打完手牌，该回合立刻结束。其余玩家按手中剩余牌的点数
计分（数字牌按面值，特殊牌 20 分，万能牌 50 分）并累加到总分。组队模式下只统计落败
一方的牌，分数记给获胜的两人组。任意席位总分达到目标分数，整局结束。

**牌数守恒。** 引擎绝不会凭空生成或丢失牌。当牌堆与弃牌堆都摸空时，该摸牌的玩家就是
摸不到牌，回合直接跳过——能离开牌堆的 107 张牌始终有明确去处。

## 电脑对手

三档难度共用同一套记牌逻辑：电脑会记录自己的手牌、所有已公开打出的牌，以及牌堆中
剩余的牌，据此推断任意对手手里各颜色的牌数。

- **简单** — 随机打出一张合法牌，随机选色，约一半情况下忘记喊 UNO，有时即使能出牌
  也会选择摸牌。
- **普通** — 为每张合法牌打分：看重干扰效果，避免喂牌给快出完的对手，优先丢掉分值高
  的牌，选择最能让下家难受的颜色；当下一位玩家不太可能反制时才叠 `+2`；当出牌者疑似
  作弊时才质疑 `+4`。
- **困难** — 额外考虑牌堆将空、保留下一位玩家最强的那一色作为后续接应、仅在自己不持有
  生效颜色时才打出 `+4`。

PVP 房间中的任意电脑席位都可以被真人顶替；对局中途掉线的玩家会由电脑接管，保证牌局
继续进行。

## 目录结构

```
include/uno/
  card.hpp        牌的数据模型、颜色、种类、分值
  deck.hpp        牌堆、弃牌堆、回洗
  rules.hpp       可配置的规则集
  game.hpp        规则引擎，以及按玩家投影的 View
  serialize.hpp   View 的小端二进制编解码
  protocol.hpp    消息分帧与负载编解码
  net.hpp         非阻塞 TCP（Windows 用 Winsock2，其他平台用 BSD socket）
  ai.hpp          电脑对手
  console.hpp     UTF-8、ANSI 颜色、原始按键输入
  ui.hpp          牌桌、手牌、菜单、提示
  player.hpp      席位控制器（玩家 / 电脑 / 远程）
  session.hpp     对局循环
  app.hpp         对外入口
src/              各模块实现，以及 main.cpp、app.cpp、online.cpp
tests/            独立测试程序
```

`Game` 是纯逻辑：输入操作，输出每位玩家各自的 `View`，完全不碰终端和网络。正因如此，
同一套引擎可以同时驱动本地界面、AI 和远程客户端；也因为 `View` 只携带该玩家自己的
手牌，任何快照都可以安全地发到网络上。

### 网络

帧格式为 `[u8 type][u32 length][payload]`。房主持有全部状态，每次状态变化后推送一份
新快照；客户端只发送操作和聊天。所有 socket 均为非阻塞，整个程序跑在单线程上，因此
房主一边服务其他玩家、一边还能玩自己的席位。某个远程玩家 30 秒没有动作，就由电脑代打，
而不是让整桌干等。

连接后必须在五秒内完成 JoinRoom，否则席位会被释放；分配席位前会校验房间码。
收到的昵称和聊天会去掉控制字符（包括 ANSI 转义）并限制长度。每个 peer 的发送队列
按整帧排队：慢客户端只会让后续帧延后，不会把某一帧截成两半；落后太多则直接断开。
帧长度也有上限，避免失步的流变成内存 DoS。

## 测试

`tests/test_uno.cpp` 约 1 秒内跑完约 1100 万条断言，覆盖：

- 108 张牌的构成与回洗，包括彻底摸空牌堆的情况
- 出牌合法性、抢回合的拒绝，以及回合状态机的五个阶段
- `+2` 叠加、万能加四质疑的两种结局、抓漏报的窗口期
- 三档难度、2–4 个席位的完整对局，断言 108 张牌始终守恒、电脑不会提交非法操作
- `View` 经由线上格式往返编解码，包括按玩家保密
- 帧解码，包括逐字节喂入、被截断的帧，以及必须被拒绝的超大长度前缀
- 房间码校验（错码必须拒绝）、发送缓冲不会截断帧、昵称/聊天的控制字符过滤
- 为每个席位渲染真实牌桌、CJK 显示宽度，以及 i18n 检查：任何消息只要残留未填充的 `{}` 占位符即判失败
